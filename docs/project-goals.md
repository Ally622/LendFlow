# LendFlow — Project Goals

## 1. What problem am I solving?

I want to build a system that helps small financial institutions, SACCOs, MFIs and lending businesses manage customers, loans, repayments and business operations in one place.

The system should reduce the need for manual paperwork and spreadsheets and make it easier for staff to know who has borrowed money, how much they owe, when payments are due, and which loans are overdue.

## 2. Who will use LendFlow?

The main users will be:

* Customers
* Loan officers
* Managers
* System administrators

## 3. What should a customer be able to do?

A customer should be able to:

* Register their personal information.
* View their loan information.
* View their repayment schedule.
* See payments they have made.
* See the outstanding amount on their loan.
* Submit or request a loan.
* Receive information about upcoming or overdue payments.

## 4. What should a loan officer be able to do?

A loan officer should be able to:

* Register and manage customers.
* Record customer applications.
* Review loan applications.
* Evaluate a customer's loan information.
* Recommend loans for approval.
* Record loan disbursements.
* Record customer repayments.
* Monitor overdue loans.
* Follow up with customers who have missed payments.

## 5. What should a manager be able to do?

A manager should be able to:

* Review and approve or reject loan applications.
* Monitor the organization's loan portfolio.
* Monitor repayments and overdue loans.
* View financial and operational reports.
* Monitor loan officers and their activities.
* Review business performance.
* Identify customers and loans that require attention.

## 6. What should an administrator be able to do?

An administrator should be able to:

* Create and manage system users.
* Assign user roles and permissions.
* Manage system settings.
* Manage loan products.
* View system activity and audit records.
* Maintain the security and configuration of the system.

## 7. What information should LendFlow track?

The system should track:

* Customer information.
* Customer applications.
* Loan products.
* Loan applications.
* Loan approval decisions.
* Loan disbursements.
* Repayment schedules.
* Customer payments.
* Outstanding balances.
* Overdue loans and arrears.
* Staff users and roles.
* Business and loan reports.
* Important system activities through audit records.

## 8. What do I want to learn during the 50 days?

By the end of this challenge, I want to understand:

* How to build frontend applications using React and TypeScript.
* How to build backend APIs using Node.js and Express.
* How to design and use a PostgreSQL database.
* How to use Prisma to work with a database.
* How frontend and backend applications communicate.
* How authentication and authorization work.
* How to design and build a real-world full-stack application.
* How to test, debug and deploy a web application.
* How to use Git and GitHub professionally.

## 9. What should LendFlow be able to do on Day 50?

On Day 50, I want someone to be able to:

1. Register a customer.
2. Create and submit a loan application.
3. Review and approve or reject the application.
4. Disburse an approved loan and automatically generate a repayment schedule.
5. Record repayments and calculate the remaining balance.
6. Identify overdue loans and customers with arrears.
7. View dashboards and reports about the loan portfolio.
8. Manage staff users and their permissions.
9. View important system activity through an audit trail.

## 10. My definition of success

I will consider this challenge successful if I can build and understand a working full-stack application from the database and backend API to the frontend interface.

I want to be able to explain how the different parts of LendFlow work, make changes to the system myself, fix bugs, write tests, use GitHub properly, and deploy the application.

Most importantly, I want LendFlow to demonstrate that I have gained practical full-stack development skills rather than simply copying code from tutorials.
